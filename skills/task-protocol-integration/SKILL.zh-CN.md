# 接入任务交互协议

[English · Skill 入口](SKILL.md) · 简体中文

`task-protocol-integration` 用于将任务交互协议 1.0 接入任务服务、应用或 Agent 客户端。适用于将现有分配映射到可移植定义、实现待办与成果交接，或通过宿主的真实接口验证协议符合性的工作。

在要接入协议的应用中工作，用用户的语言回复。先定位同版本的协议仓库。在随仓库分发的目录结构中，从本 Skill 的**真实目录**向上两级就是仓库根目录，遇到符号链接先解析实际位置。如果只复制了 Skill 文件夹，使用工作区中同版本的协议仓库，或从官方仓库获取对应版本。定义 Schema、消息 Schema 和推演用例共同描述同一版本。[协议仓库](https://github.com/alcheme-labs/task-interaction-protocol) · [协议总览](../../README.zh-CN.md)

## 找到一次真实交接的责任方

从用户入口跟到读取最终成果的人或 Agent，找到实际的分配、认证上下文、任务服务、持久化成果与读取接口。根据用户请求确定接入位置。

- **调用已有服务。** 用 `describeTaskProtocol` 发现获权版本、能力和目录。将应用使用的传输方式或 Agent 工具映射到已有服务，读取该服务的操作回执和视图。任务进度由该服务维护。
- **实现任务服务。** 找到现有定义发布方、分配存储、事务边界、内容所有者和受信来源适配器，在现有责任方上扩展。只有内核安装后继。宿主自行选择传输和存储方式。详细设计第 6 节给出一个实际宿主的映射方案。[存储与接入](../../docs/任务系统协议与运行边界_详细设计.md#storage)

## 接通协议操作

1. 每份独立提交的成果或决定对应一个活动，填写一个责任角色和一个子目标。明确映射输入、输出、检查和出口。用户要求由不同的人负责时声明 `distinctRoles`，启动时核对别名背后的实际主体。候选判定用检查，等待受信来源的事实用等待，通知用 `after`。同时校验定义和目标宿主的实际能力。缺少能力时指出受影响的路径并保留原要求。[定义 Schema](../../definition.schema.json) · [可执行样例](../../review.task.json)
2. 分清登记与派发。`validateDefinition` 通过后，获登记授权的 `publishDefinition` 使用预期基线和稳定请求号。用 `readDefinition` 按回执中的精确修订读回并核对完整正文。只要求登记时，到读回即完成。启动需要已要求且获授权的分配、固定修订、角色绑定和输入。用实际绑定的首位执行者身份读取 `getWork`。外部来源身份从宿主受信配置和认证中绑定。[启动与绑定](../../docs/任务系统协议与运行边界_详细设计.md#activation)
3. 沿用协议消息封套，包含 `protocolVersion`、`op`，以及 `params`、`result`、`error` 中的一项。调用 `submitResult` 时携带当前的 `workId`、`round`、`expectedViewSeq`、`requestId` 和声明过的输出。调用者身份从认证上下文取得。遵循 `allowedActions`、输入可选性及本主体实际能读的资料版本。收到 `pending` 表示原尝试已经持久接管，内核继续处理。拒绝可在原轮补正。退回则根据指定成果与可改范围开新轮。[消息 Schema](../../messages.schema.json) · [待办与资料](../../docs/任务系统协议与运行边界_详细设计.md#work-view)
4. 在服务边界，`accept` 原子提交正式成果、交接、唯一后继与回执。匹配的 `signal` 触发 `resume`，以同样的事务保证消费指定等待并安装一个后继。按等待类型核验来源、对象、关联请求及版本或游标。来源只读自己的回执。响应不明时，在当前授权下，用**原键和原载荷**查回或重投。外部写入结果未明时，按提供方的原请求号核实。终态可读回最终交付 `finalResultId` 和结束决定 `decisionResultId`。[交接事务](../../docs/任务系统协议与运行边界_详细设计.md#transitions) · [等待与恢复](../../docs/任务系统协议与运行边界_详细设计.md#external)

## 验证接入结果

只要求登记时，以获授权身份按精确修订读回即完成。需要测试运行行为或对比解释端时，可以按仓库内的演练命令校验 `review.task.json`，登记到临时 SQLite 库。在新进程中按登记回执的修订读回，把读回的正文和 `conformance.json` 同时交给 `replay.py` 与 `replay.mjs`。两端应复现三条用例的位置、回执和最终内容。用 `author.py describe` 查看本地演练支持的范围。向量中的执行者和来源字段属于测试输入。[可执行命令](../../README.zh-CN.md#local-walkthrough) · [符合性向量](../../conformance.json)

从接入系统的真实入口验证用户要的每项能力。以复核队列为例，撰写者读首份待办并提交，复核者读取新待办并附理由退回，撰写者修订后由复核者采纳。重启宿主，以获权读者身份读取最终采用的版本和结束决定。若仅要求登记，验收精确修订在重启后可读回，且派发数为零。覆盖适用的例外场景，包括丢响应后重放、同键换内容、撤权，以及并发提交或信号只产生一次交接。报告实际运行的路径和从其责任方读回的结果。[宿主验收用例](../../docs/任务系统协议与运行边界_详细设计.md#tests)

## 可选配套协议

- **开发独立服务时**，ServiceSeed（原名 ServerAgent）约定 Agent 如何在明确的服务契约和权限下创建、连接与维护服务。[ServiceSeed](https://github.com/alcheme-labs/ServiceSeed)
- **接入用户自有 Agent 时**，Agent Bridge Spec（`local-agent-bridge`）覆盖应用和 Agent 的连接与授权。任务操作交给任务服务，成果接纳、交接与回执由该服务负责。[Agent Bridge Spec](https://github.com/alcheme-labs/agent-bridge-spec)
