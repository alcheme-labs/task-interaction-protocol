Before acceptance · check

checkArtifact@1 compares the candidate with the requirements. Return a verdict directly or via deliverCheck. All pass → accept. A rejection reopens the round for correction.

After commit · after

For example, wait.opened → notify@1. A reminder can be retried. Delivery updates only its own record.

03

How activities hand off work

Check the next assignee and input permissions, then register newly bound resources.
accept takes the first matching rule in order, or the default exit

next Continue

Open work for the target role. Start with empty inputs and carry only what with maps on this edge.

return Revise

Locate the original work and inputs by the specified result. Open a new round with its baseline, reason and edit scope.

wait Wait

Register the wait and its continuation. Pin known inputs now and fill in the fact when it matches.

end Complete

Pin the final deliverable and the result that chose it. The instance enters COMPLETED.

Trusted source · Fact delivery

Check the wait ID, source, subject version and condition. A mismatch leaves the wait open at W1.

Kernel · Match and handoff

resume · Consume wait

Add the matched fact. Consume W1 once and open the next work item or end in the same transaction.

When the successor is unavailableIf a fact matches but required materials are temporarily unreadable, keep the fact and wait. Resume when access returns. Repeat delivery reuses the receipt.
